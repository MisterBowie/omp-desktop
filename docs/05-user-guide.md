# OMP Desktop 使用说明

## 仅 OMP 产品（2026-10-21 本机源码）

用户已选择按新 OMP 项目处理，不兼容或迁移旧 Pi 会话。本机源码的所有新会话、
宿主默认和执行路径统一为 OMP；旧 Pi 记录不展示或导入，磁盘原文件保留。应用不再
启动或打包 Pi worker，也不自动连接旧远程 Pi Host。此变更尚未打包安装或发布，
现有安装包尚未应用；本轮没有操作用户安装态数据。

## 自动记忆（0.1.3 起）

入口为左下角齿轮 → “记忆”。仅 OMP 修复版安装后，新建会话即可按开关积累记忆。

- “自动保存”和“自动读取”独立开启，默认均关闭。保存默认每 4 个用户轮次执行，
  正常退出应用时补存剩余内容；读取在新会话首轮与压缩上下文时检索。
- 开启前先等待所有 OMP 会话及后台工作结束。记忆整理可能调用会话模型并增加
  Token，本轮不下载向量模型，Auto-Learn 保持关闭。
- 下方选择项目、worktree 或临时会话，可查看、搜索、刷新记忆。每个实际工作目录
  独立存储；关闭开关保留内容。“清空”需要再次确认，只清除所选范围的自动记忆。
- 手动项目记忆及聊天记录继续独立保留；开启或清空后不会重新导入旧聊天。

实现与验证见[自动记忆验收](validation/OMP-automatic-memory-20261020.md)。

以下保留此前各阶段的使用记录。

## 尚未发布的会话 worktree 功能（2026-10-18 本机源码）

以下功能只在 `codex/omp-session-operations` 源码工作树，公开 0.1.0 安装包尚未包含。

- 项目菜单选择“新建隔离会话”：需要本地 Git ≥ 2.29、已有提交且当前在分支上。
  总是创建新的 OMP 会话，从已提交的分支内容建立工作树；原项目的未提交/忽略文件
  不会带入，依赖也不会自动安装。
- 会话列表显示隔离状态。会话菜单可预览“合并到项目”、从项目同步提交，或显示
  实际工作树目录。预览后必须确认合并；未提交修改会先提交到会话分支。
  项目脏文件、分支切换或预览过期会拒绝；冲突留在工作树中解决后重试。
- Skill、手动项目记忆、MCP 和插件仍使用原项目作用域；原生工具、计划工件、文件面板与
  聊天文件链接使用工作树。切换项目不改变后台会话目录。
- 运行中不能合并、同步或删除；Main 先回收原生进程，再执行 Git 变更。
  删除菜单第一次操作会提示未合并内容丢失，确认后删除自有工作树及分支。
  归档与正常退出保留工作树。创建中断或目录缺失不会回退原项目执行。

本轮只提供本地 OMP 会话级工作树；自动初始化、`.worktreeinclude`、端口环境和
子代理独立工作树尚未接入。源码数据库升级到 v22，并在从 v21 升级前备份；回退到
旧应用时需使用升级前数据库备份。开发验收只操作临时数据，没有迁移用户安装数据。
详见[验证记录](validation/OMP-worktrees-20261018.md)。


本项目在 PI-Desktop 界面基础上接入完整 OMP 运行时。当前版本为 **0.1.0**，
从 [OMP Desktop 稳定版](https://github.com/MisterBowie/omp-desktop/releases/tag/v0.1.0)
或 [最新下载](https://github.com/MisterBowie/omp-desktop/releases/latest) 选择对应平台。
彩色像素π图标、Write/Edit后的LSP诊断及自己的GitHub更新源均包含在内。

## 会话交互增强（2026-10-18 本机源码，尚未发布）

以下功能在 `codex/omp-session-operations` 工作树中；现有公开安装包不会自动包含
未发布源码。版本仍为 0.1.0，未修改用户安装和数据。

- **Todo 清单**：助手使用 OMP 原生 `todo` 后，输入框上方显示进度和当前任务；点击
  可展开全部阶段、任务状态与阻塞原因。切换或恢复会话时显示所属原生清单，只读。
- **Skill 命令**：输入 `/skill:` 选择内置、用户或插件技能，例如
  `/skill:技能ID 具体要求`。旧 `/技能ID` 在不与应用/模板命令冲突时仍可使用。
  执行时重新核对所属项目；技能正文仍按需读取。目标回合没有 Skill 加载器时，
  请排队到下一回合；不会静默忽略技能要求。
- **运行中输入**：默认 Enter 发送排队跟进，Alt+Enter 插入当前回合。
  排队项可编辑、移除、排序或优先发送；插话不会新建宿主回合。当前仅支持文本。
- **会话侧栏**：项目折叠后仍显示运行或待审批状态，会话行显示日期；菜单可复制
  标题、项目路径和会话 ID。临时会话不会显示空项目路径复制。

本轮本机验证与安装态 UI 验收边界见[交互验证记录](validation/OMP-session-ui-20261018.md)。

## 安装与开始使用

### 全局用户子智能体（2026-10-22 源码修复）

设置中启用的 `~/.agents/subagents/*.md` 用户定义现可用于 OMP 原生 `task`，例如
`code-implement`。指定模型按供应商 ID、厂商标识或名称匹配已配置供应商；定义未
指定模型时继承当前会话模型。编辑、禁用及模型配置变化在下一条消息前刷新，保留
原会话历史。该修复需要包含此次源码的新安装包；既有 0.1.4 安装不会自动获得它。

未声明工具时只读，`inherit` 继承 OMP 可用的原生工具；Pi 专属工具和宿主工具的
子会话支持仍以 OMP 实际能力为准。子调用沿用父会话权限门，逐子级权限覆盖暂不
支持；无效定义带诊断排除。若项目 `.omp/agents` 有同名定义，须先改名消除冲突，
避免覆盖设置中的工作者。本轮不更改真实用户配置或自动迁移其他应用的数据。

| 平台 | 分发格式 | 已执行的安装路径 |
| --- | --- | --- |
| macOS Apple Silicon / arm64、Intel / x64 | DMG；ZIP 为另一份分发格式 | 两种架构各自从DMG复制实际应用后运行 |
| Windows x64 | setup EXE；portable EXE 为另一份分发格式 | NSIS 安装器实际安装后运行 |
| Linux x64 | AppImage；另提供 DEB/RPM | 实际 AppImage 提取后运行 |

当前Mac分发未公证，未签名或临时签名包使用手动更新。首次打开说明随ZIP提供。
0.1.0的Mac双架构、Windows、Linux各自通过包内严格15项和实际安装8项；
先前M7的日常使用与真实升级回退记录见[M7验收](validation/M7-native-release-20261016.md)。没有用构建成功代替安装验收，
也没有把 DEB/RPM 系统注册、portable 的独立用户流程或其他CPU架构写成已验证。
Windows 的 Bash 工具沿用 PI 的 Git for Windows 前提；项目本身使用的语言工具仍由项目提供。
Linux使用系统sans字体；CI截图的中文项目名出现缺字方框，未证明CJK字体在该runner可用，
中文路径的实际操作/隔离已通过。需要中文显示时，系统应提供相应CJK字体；产品没有声明捆绑该字体。

1. 打开自己的项目目录，创建 OMP 会话；会话绑定创建时的项目、引擎和运行时。
2. 在提供方/模型设置中配置自己的受支持 HTTP 模型。普通验收只使用本机假模型，
   不预置或调用真实模型账号；当前 DeepSeek 服务恢复由用户另行通知。
3. 通过 Composer 发消息。工具审批会在执行前显示；拒绝、批准一次、自动权限是不同选择。
4. 用 Stop 结束执行中的回合。应用保留原生历史；重新打开会话读取历史不会重新执行工具。
5. 可以切换到另一项目继续工作。后台会话的相对路径仍绑定它自己的项目。

## 编码时的 LSP

`0.1.0` 已包含此前 `0.15.3-lsp.1` 的修复，会在写入和编辑匹配语言的代码文件后自动获取 LSP 诊断，
在工具完成前返回给模型，并在 Write/Edit 工具卡中显示。旧公开 `0.15.3-m7.1` 的
编辑后检查默认关闭，Write 卡也会遗漏诊断；0.1.0已成为新的稳定下载入口，旧M7测试版保留作历史。

项目需要可运行的对应语言服务器和正确的项目根标记，例如 TypeScript 项目的
`package.json` / `tsconfig.json`。OMP 保留原生自动发现和 `lsp.enabled` 开关；
没有服务器时，工具注册本身不能提供语义分析。本次不自动安装各语言服务器。

运行时使用隔离的 HOME 和 PATH；NVM 等用户 shell 路径不会直接继承。可以在所选
项目根的 `.omp/lsp.json` 中明确指定本机解释器及服务器，示例中的路径应替换为实际路径：

```json
{
  "servers": {
    "typescript-language-server": {
      "command": "/absolute/path/to/node",
      "args": ["/absolute/path/to/typescript-language-server/lib/cli.mjs", "--stdio"],
      "rootMarkers": ["package.json", "tsconfig.json"]
    }
  }
}
```

TypeScript 编译器需与服务器一起安装。修改服务器配置后重新建立运行时会话，或使用原生
`lsp reload`；服务端状态、诊断、定义、引用等功能可通过 `read xd://lsp` 发现。
自动写入/编辑诊断由运行时执行，不要求模型每次再主动调用一次 `lsp diagnostics`。
语义导航工具的选择仍由模型决定，不保证每一回合都产生独立 `lsp` 工具调用。

本次真实 TypeScript 服务端、安装包界面和重启历史的验证记录见
[LSP 本机专项验收](validation/LSP-coding-local-20261016.md)。

## 与 PI 界面的关系

布局、Composer、审批卡、侧栏和工具展示继续复用 PI 结构。应用名称、图标、appId、更新来源、
profile/数据/凭证命名已独立；不会自动迁移或覆盖现有 PI/OMP 用户配置。内部包名和原作者、
许可证声明保留。OMP 原生会话是历史来源，桌面保存索引和显示投影。

OMP 特有工具和子代理结构通过适配层显示；没有专用展示的结果仍可能使用通用工具卡。
子代理的单独停止等未支持入口遵循能力拒绝，不伪装为可执行能力。支持范围和证据见
[任务看板](04-task-board.md) 与各阶段验收记录。

Plan/Goal 仅在已经验证的非 Cursor 路线开放，保留整批工具零副作用等严格契约。
**Cursor + Plan/Goal 明确不支持并拒绝**；桌面当前也没有接通 Cursor 传输。

## 0.1.0 的版本重置与更新

从 `0.15.x` 测试版首次切换到 `0.1.0` 需要手动安装；版本序列重新开始，应用不会自动降级。
本机macOS实际覆盖安装已验证原有OMP项目保留。后续版本在设置/版本入口手动检查更新，
更新来源固定为本项目的 GitHub 稳定发布，历史测试版不会被当作稳定更新。

| 安装形式 | 更新方式 |
| --- | --- |
| 未签名或临时签名 macOS | 检查 GitHub 后打开下载页，手动替换 |
| Developer ID 签名 macOS | 下载进度与重启安装；当前未声称真实签名包已发布 |
| Windows NSIS 安装版、Linux AppImage | 应用内下载与安装/重启 |
| Windows portable、Debian、RPM | 检查后手动下载 |

Mac 未公证版本首次启动如被系统拦截，按 ZIP 中的 `OMP-Desktop-macOS-opening-help.txt`
操作。更新检查失败可以重试；只下载到完整安装包后才允许触发安装。

## 备份、升级与回退

先完整退出应用，再备份整份 OMP 数据和 profile，保留其中的凭证材料和文件权限，
不要只复制 SQLite。产品数据默认在用户 HOME 的 `.omp-desktop`；Mac 默认 profile 已实测为
`Library/Application Support/OMP Desktop`。其他平台的 profile 由系统 Electron userData 位置管理，
测试运行报告记录其实际路径；测试中的自有 `--user-data-dir` 不是用户默认路径的证明。

M7 人工演练使用固定公开 M6 `0.15.2` 安装包，实际替换为 `0.15.3-m7.1`，在同一 profile/data
读取历史并完成新工具写入；关闭后恢复先前备份，再实际运行 `0.15.2`。备份和还原清单必须
逐文件相同，历史读取不能增加模型请求，旧工具不能重放，回退后仍可发送新回合。

恢复备份会让应用历史回到备份时刻；项目文件继续保持实际文件状态。需要回退项目代码时，
由项目自己的 Git/备份处理。该演练使用相同 OMP/schema，不能据此推定任意未来版本都可降级；
该M7测试包没有发布自动更新feed，因此上述演练验证的是人工安装包和数据备份流程；
0.1.0开始使用自己的GitHub稳定更新清单。

## 故障与维护信息

提供方失败应保留错误行和诊断，服务可用后可发送新回合。M7 修复了原生401错误在历史刷新时
变成成功空回复的问题。断连重试和恢复已用真实本机HTTP边界验收；不据假模型断言真实服务质量。

维护所需的固定版本、构建命令、升级演练及回退证据见 [发布检查单](06-release-checklist.md)。
当前观测覆盖有限示例与40回合会话；资源采样和真实UI截图随维护证明保存，不是通用性能基准。

## HTML 文件的打开方式

当前源码在聊天中的 `.html` / `.htm` 文件引用上提供右键菜单：
**打开方式 → 文件管理器 / 内置浏览器 / 默认浏览器**。
普通点击保持原来的预览行为。“默认浏览器”使用系统对 HTML 的默认文件关联；
若关联的是编辑器，系统会打开该编辑器。引用不存在或目的地不可用时会提示错误。
