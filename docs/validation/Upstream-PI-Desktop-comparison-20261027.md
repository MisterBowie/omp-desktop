# PI-Desktop 上游更新与 OMP Desktop 的差异对照

- 日期：2026-10-27
- 上游：`vastsa/PI-Desktop`，0.15.3 至 0.22.0-beta.1，HEAD `5aa25388`（2026-10-26）。最新稳定版为 0.21.0（2026-10-24）。
- 分叉基线：PI-Desktop 0.15.2（`0111e306`，2026-09-21）。OMP Desktop 从该基线分叉，之后的改动记录在根目录 `HANDOFF.md`。
- 本地：`main` 为 `0f2bb931`（含 R17、R18、R19，均未推送）。

本文件是决策参考，不是实现计划。每条判断都是建议，移植前需要按第 2 节的证据限制重新核实。

## 1. 摘要

1. **执行引擎不同**。上游是 Pi agent-runtime，我们是 OMP 子进程（`omp --mode rpc-ui`）。上游 Pi 运行时里的修复（托管搜索、ToolSearch、pi-ai 供应商协议、Pi 压缩与委派）对我们不适用；OMP 已有等价实现的，也不需要移植。
2. **值得移植的主要是与引擎无关的部分**：渲染层交互、主进程里的 MCP、浏览器、文件、代理与设置页。这些大多是 S 级改动。
3. **需要先处理的真实问题有两个**，比功能更紧急：
   - OMP 子进程不接收任何代理设置，需要代理才能连通模型服务的用户会被挡住（第 8 节第 1 条）；
   - 重载渲染进程后，待审批和待回答的卡片丢失，OMP 回合会一直等待（第 8 节第 2 条）。
4. **R19 已补上**：OMP 会话的生成速度（之前一直显示"—"），以及上游 0.21.0 的每轮用量胶囊（第 6 节）。
5. 上游 0.21.0 之后的新功能（内联可视化、后台任务面板、Live Voice、SSH 工作区）要么依赖 Pi 运行时，要么与当前产品范围冲突，已在第 5 节逐条标明。
6. **Java 文件**：工作面板已支持 `.java` 的打开与高亮，聊天里的 `.java` 路径可点击；缺口是 `path:line` 不跳行（第 2 节已核实）。`.kt`、`.gradle`、`.groovy`、`.scala`、`.kts`、`.properties` 的支持情况未核实。

## 2. 方法、证据与限制

- **上游历史**：提交标题（`git log 0111e306..5aa25388`）、GitHub Release 正文（PR 列表）、应用内更新记录（`packages/shared/src/changelog-*.ts`）、两个版本的文件清单对比。
- **我方状态**：以 `app/` 代码为准。下列"已核实"项是本轮实际读过代码或文件得出的结论；其余条目来自上游提交标题、PR 列表与文件清单，表中标 `[推断]` 或"未核实"，移植前需读上游 diff。
- **方法限制**：本轮没有派出子代理，也没有逐个读上游 diff。上游版本与 PR 归属来自 `git log`、Release 正文与应用内更新记录。
- **已核实**（路径以 `app/` 为根）：
  - OMP 会话不接收代理：`packages/omp-runtime/src/isolation.ts` 的 `buildOmpRuntimeEnv` 只在传入 `proxy` 时写入代理变量；`apps/desktop/electron/main/runtime/omp-session-wiring.ts` 创建会话 supervisor 时只传 `desktopStateRequired`，没有代理；`bootstrap/omp-sessions.ts` 的 `networkProxy` 只传给了 marketplace。
  - `RuntimeRunner.openRequests()`（`packages/omp-runtime/src/session/runner.ts`）存在，`apps/desktop/electron` 中没有调用。
  - `apps/desktop/src/lib/chat-links.ts` 识别文件引用时剥掉 `:line[:col]`，行号不生效。
  - Java 已有支持：`components/workpanel/FilesTab.tsx` 的语言表、`lib/shiki.ts` 的 java 语言、`lib/chat-links.ts` 的扩展名表、`transcript/shared.tsx` 的代码文件判断，都包含 java。
  - `features/chat/composer/hooks/useComposerSubmit.ts`：斜杠命令分支在命令 await 结束后才调用 `clearDraftForKey`，执行期间输入的新内容会被清掉。
  - `components/Sidebar.tsx` 的 `placeMenu` 以 `window.innerHeight - 220` 限位。
  - 内置 `pi.file-manager` 版本为 0.5.2（`resources/plugins/pi.file-manager/manifest.json`）。
  - token/s 根因与用量胶囊移植见 `docs/validation/Token-throughput-20261027.md`，本文不重复。
- **未核实**：上游 0.5.3-pi.1 的具体改动（含暗色查找框）；0.22 工作面板菜单的实现细节；上游 `.java` 高亮与 `App.java:42` 行号跳转的实现（只见到更新记录文字）。
- **未做**：没有运行上游应用，没有对比两边的界面，没有运行上游测试。
- **版本归属**：0.15.3–0.15.10 中有些修复实际早于基线合入（发布分支热修），表中注明了推断依据。

## 3. 产品基线的根本差异

| 维度 | 上游 PI-Desktop（0.22.0-beta.1） | OMP Desktop（main，0.1.6 正式版） |
|---|---|---|
| 执行引擎 | Pi agent-runtime（pi-ai 1.3.0、pi-agent-core、pi-coding-agent），桌面侧 sidecar | `omp --mode rpc-ui` 子进程，固定 OMP 18.3.0，fork `edec3898`，补丁 `62bc57b+omp-desktop.7` |
| 会话与历史 | host-core SQLite 为主；Pi 会话文件可被发现与合并 | OMP 原生 JSONL 为准；桌面只存索引与显示投影；不扫描 Pi 会话 |
| 工具与审批 | Pi 工具加桌面 gate | OMP 原生工具；`omp-desktop-gate` 扩展在 `tool_call` 钩子上执行前阻断 |
| 子代理 | Pi 委派（注册表，可单独停止） | OMP 原生 `task`；不能单独停止（OMP 没有对应 RPC）；子代理没有 UI |
| 待办 | host-core 会话待办，0.21.0 后合并进 TaskDock | OMP 原生 todo，只读展示 |
| 后台任务 | Rust 执行器实现的后台 Bash（0.21.0） | OMP 负责（默认超过 60 秒转后台）；桌面没有任务界面 |
| 模型与供应商 | pi-ai 模型目录与供应商，支持 OAuth 账户 | 桌面投影为 OMP models.yml；不支持 OAuth，入口已隐藏 |
| 插件 | `.piplug` 插件 API（插槽、草稿、OAuth、网络重定向），PI 插件中心（评分、评论） | 内置 pi.browser、pi.file-manager 两个视图；插件市场由 `omp plugin` 管理（ADR 0333） |
| 记忆 | 上游记忆能力 | OMP Mnemopi 自动记忆（0.1.3，ADR 0330）；手动项目记忆保留 |
| 分支与 fork | 支持（0.15.7 起可 fork 已完成回复） | 关闭（OMP `branch` 能力为 false） |
| 语音 | 本地语音输入（0.15.9）；Live Voice（0.16.0） | 无 |
| 生图 | Pi sidecar 的 GenerateImages | 无（OMP 会话没有该工具） |
| 远程 | 远程 Pi Host、SSH 工作区、远程升级 | 入口关闭（产品约束） |
| 云同步 | 有（实验性） | 首期不做 |
| 数据目录与身份 | `~/.pi-desktop`，PI-Desktop 的 appId 与更新源 | `~/.omp-desktop`，独立 appId、凭据命名与更新源（MisterBowie/omp-desktop） |
| 发布 | GitHub Release（vastsa/PI-Desktop） | 正式版与测试包按请求发布；本地 `main` 未推送 |
| 许可 | LGPL-3.0 | 派生自上游源码，保留上游版权与许可声明（见根 `AGENTS.md`） |

## 4. 建议的移植顺序

判断标准：先看对真实使用的影响，再看成本。P0 是要先处理的问题；P1 是低成本的体验修复；P2 需要设计或多处改动；P3 需要先做决定，或依赖 OMP 核心补丁（需要 ADR 与用户授权）。

### P0：真实影响，建议优先

| # | 项目 | 来源 | 成本 | 说明 |
|---|---|---|---|---|
| 1 | OMP 子进程接收代理设置：自定义代理直接传入；系统代理按供应商地址解析 | 0.17.0 #1432；0.19.0 #1592 相关 | M（最小 S） | 第 8 节第 1 条。R18 的市场 CLI 已示范做法（`cli.ts` 接收 `proxy`），可复用 |
| 2 | 重载渲染进程后恢复待审批与待回答的卡片 | 0.16.0（#9eaab83a 相关） | M | 第 8 节第 2 条。`omp-runtime` 的 `openRequests()` 已存在，桌面没有调用 |
| 3 | 切换网络模式时保留自定义代理；切回时恢复已保存的地址 | 0.19.0 #1592；0.19.1 #1618 | S | 同一段代码。当前切换会丢失 url 与 bypass |

### P1：低成本，体验明显

- 文件预览一组（整体 M）：`path:line` 跳到对应行；行内代码确认是真实文件后才变成链接，支持 Windows 路径与工作区外绝对路径；普通点击先启动文件管理器，失败时提示；补全扩展名（scala、groovy、gradle、kts、properties）。
- 文件管理器暗色主题下的查找框（S）：同步内置插件到 0.5.3-pi.1。
- 工具详情默认收起（S）：OMP 的长输出会把回答挤出视野。
- Composer 模型列表显示已配置的上下文上限（S）：界面显示值与 OMP 实际使用的值一致。
- 最近使用的模型（S）：纯渲染层。
- 免密自定义接口（S）：后端、OMP 投影与 OMP 运行时都已支持，只缺界面选项。
- Todo 正在执行的一步加光带，完成项改删除线（S）。
- @ 文件建议显示完整相对路径（S）。
- 项目路径导航，对话顶部就地改标题（S）。
- 激活项目时恢复已归档状态（S）。
- 消息工具栏显示时间戳（S）：数据已有。
- 输入框按 ↑ 召回同一会话内已发送的内容（S）。
- 浏览器接受 `localhost:端口`（S）。
- 插件视图在非 100% 缩放下错位（S）。
- 去掉 Cmd/Ctrl+R 误刷新（S）。
- 大纲跳转后不再弹回底部（S）。
- 更新提示关闭后记住，并取消该版本的下载（S）。
- 项目对话框打开时隐藏停靠的原生视图（S）。
- 选择已关闭分组中的目录时重开该分组（S）。
- Skill 工具返回技能文件位置（S）：技能的 scripts/、references/ 目前无法定位。
- 侧栏底部的项目菜单按实际尺寸定位（S）。
- 模式芯片随字号缩放（S）。
- Windows 下插件工作区路径的大小写与斜杠不同时仍能匹配（S）。
- AskTool 连续提问时按请求隔离状态（S）：目前会沿用上一题的选项。
- 公式复制为 TeX（S）；SVG 作为文件而不是图片发送（S）；长斜杠命令 chip 换行（S）。
- 侧栏运行状态的呼吸动画限制循环（S）。
- 计划任务串行启动改为并行（S）。
- 窗口最小尺寸降到 800×560（S）：改小前要核对侧栏加工作面板的布局。
- 转录写入器撕裂尾行的修复（S）：先看上游 diff 再决定。

### P2：中等成本，需要设计或多处改动

- Markdown 表格复制、导出 CSV、展开预览（M）。
- 大型工具输出分页显示（M）。
- AskTool 历史问答以问答卡片显示（M）：按 OMP `ask` 工具的 details 结构适配。
- 上下文面板的会话总耗时与模型响应耗时（M）：R19 已有 `responseDurationMs`；三段拆分（供应商等待、模型流式、工具）还需要把 `ttft` 映射进来。
- 工作面板标签右键菜单：关闭、关闭其他、关闭全部（M）。
- MCP 停止时取消进行中的调用；每个服务单独设置连接超时（M）。
- Windows 下 npx 类 MCP 服务的启动解析（M）。
- Chromium 渲染进程崩溃的缓解与恢复（M）。
- 中转或网关模型匹配官方元数据（M）。
- 技能包资源不受文档大小上限限制（M）。
- "立即发送"的消息在投递前可撤回（M）：需要 host 队列支持。
- 计划任务保存模型、权限与思考档位（M）。
- 内置浏览器打开项目外的本地文件（M）：照搬上游的边界，只放开导航目标。
- 对话中的 MP4 用系统播放器打开（S）。

### P3：需先决策，或依赖 OMP 核心补丁

- 单独停止某个子代理：需要 OMP 新增 RPC，属于 fork 补丁，需要 ADR。
- 后台任务面板：需要 ADR。注意 OMP 的语义是"本轮挂起到任务结束"，与上游相反。
- 分支与 fork 已完成的回复：需要 OMP 支持分支。
- 提示词增强、会话标题、插件 `agent.complete`：R12 删除 Pi 运行时前要选定替代方案（插件化，或改用 OMP）。
- 图片原位标记（M）：可用 OMP 原生的 `[Image #N]`，不改 OMP 核心，但要同时改附件存储与历史回放。
- 会话引用标签与粘贴会话链接（M）：scheme 不能用 `pi-desktop://`，会与 PI-Desktop 冲突。
- 每条提示单独选择 MCP 服务（M）：OMP 市场插件的 MCP 归属还没定（ADR 0333）。
- 对话显示模式（M–L）：包括思考显示开关与光带。
- 内联可视化（L）、Live Voice（L）、本地语音输入（L）、自定义数据目录迁移（L）：都是独立的大功能，建议单独立项。

## 6. R19 覆盖的范围

R19（`0f2bb931`）已经完成：

- OMP 会话的生成速度：适配层把 OMP 原生的请求时长映射为 `responseDurationMs`，实时与历史一致（对应上游 0.20.1 "模型响应速率统计更准确" 的 OMP 等价做法）。
- 每轮用量胶囊：完整移植上游 0.21.0 的 `TurnUsageCapsule`，显示速度、总量，悬停看缓存读取、输入、输出与合计（对应 0.21.0 第 4 条的胶囊部分）。

仍未覆盖：

- 会话总耗时与三段拆分（0.18.0 第 13 条、0.20.1 第 16 条）：前端与 `ttft` 映射未做。
- 胶囊只统计渲染出来的助手消息片段（与上游一致），只产生工具调用、没有文字或思考的请求不计入。
- 中断且供应商未报告用量的 OMP 回合不显示速度（第 8 节第 11 条）。

## 10. R19 与上游胶囊的实现差异

| 方面 | 上游（PI-Desktop 0.21.0） | R19（OMP Desktop） |
|---|---|---|
| 时长来源 | Pi 1.1.0 的 `AssistantMessage.durationMs`（单调计时）；缺失时退回 sidecar 秒表 | OMP 的 `message.duration`（provider 测量，包含首 token 等待）；缺失时退回转换器秒表 |
| 中断回合的输出 token | 用可见文字与思考估算（每 4 个 Unicode 码点一个 token） | 不估算，只使用供应商用量（第 8 节第 11 条） |
| 弹层挂载 | `portalToBody`，依赖上游的 `portal-visibility` 模块（可在对话框打开时隐藏） | `createPortal(…, document.body)`，与我们现有的上下文检查器一致；没有移植 portal-visibility |
| 组件与样式 | 基线 | 从上游 HEAD 复制，结构与类名一致 |
| 文案 | `usageTurnAria`、`usageTotal` 等，9 种语言（含 pt-BR） | 同名 key，8 种语言（我们没有 pt-BR） |
| 测试 | 大量对源码与 CSS 文本的正则断言 | 按仓库规则，不测源码文本；改为行为测试（`turnUsageBreakdown` 边界、原生 e2e）与真实 Electron 渲染 |
| 会话耗时拆分 | 0.18.0 与 0.20.1 的 `useSessionTiming` | 未移植（第 6 节） |
