# OMP 自动记忆本机验收（2026-10-20）

本轮按用户同意的方案接入 OMP 18.3.0 自带的 Mnemopi。功能源码与本机候选已完成；
用户随后明确授权本地提交原生补丁及更新锁定。原生提交为
`edec3898d44071206ec201beebea432a2786bd8c`，桌面锁定推进到
`62bc57b+omp-desktop.7`。应用仍为 0.1.2，存储 schema 22 不变。
桌面修改尚未提交，原生提交尚未推送，未打安装包或发布，也未替换安装态应用。

## 行为与入口

- “设置 → 记忆”提供“自动保存”和“自动读取”两个独立开关，默认均关闭。
- 自动保存默认每 4 个用户轮次执行，正常退出应用时补存剩余内容；开启、清空、恢复旧会话均不会自动导入已有历史。
- 自动读取在新会话首轮及压缩上下文时检索。关闭开关保留数据库。
- 项目、worktree 和临时会话按实际执行目录隔离；支持分页查看摘录/提炼事实、本地文本搜索、刷新与绑定选择范围的二次清空确认。
- Mnemopi 是数据库唯一责任方，Rust 宿主仅持久化开关，桌面通过结构化 RPC 管理。手动项目记忆、聊天记录及原生 CLI 数据独立。
- 不下载 embedding 或小模型；本轮使用本地文本检索，记忆提炼绑定会话配置的模型，可能增加 Token。Auto-Learn 保持关闭。
- 改开关/清空前须确认 OMP 没有活动回合、子代理、后台 Bash/eval/handoff 或待投递结果，再回收空闲写入进程。维护期间新消息等待，完成后唤醒跟进队列。
- 开启前验证原生协议及 Mnemopi 可用性；每次启用记忆的会话启动也验证对应记忆库实际初始化成功。旧接口或初始化失败直接拒绝，子进程按原有所有权语义回收。

`app/packages/omp-runtime/src/memory-{config,policy}.ts` 及现有会话维护/启动边界；

`app/patches/oh-my-pi/manifest.json`。此前 `.6` 身份追加进 history，未覆盖历史事实。

管理进程不调用模型，使用独立无凭证的本地关闭端口模型目录完成原生启动。

数据库路径为 `<desktopData>/omp-memory/<sha256(normalizedAbsoluteExecutionDirectory)>/memory.db`，
不进入项目目录，不随运行目录回收。

## 失败与修正记录

1. 最初缓存路径/全局 pnpm 版本不符导致离线安装失败；改用现有 pnpm 10.34.5 包装器及正确本地缓存。原生缺失 NAPI/tool views 后使用已存在的 18.3.0 addon 和锁定生成步骤。
2. 最初路径包含判断参数顺序颠倒、原生管理启动没有模型目录，均由真实原生烟测发现后修正。管理进程使用无凭证的关闭本地端口目录，仍不发送模型请求。
3. 高并发 runtime 测试触发原有 5 秒超时，限为 2 个 worker；未放宽超时。旧 0.1.1 参考资源被严格校验拒绝后，从干净的原生 `.6` 和桌面 0.1.2 重建正确参考；最终 .7 使用标准新产物。
4. 早期原生全仓 `bun check` 因 `.6` 既有 agent-loop 文件格式失败，不记通过。新增原生文件已格式化；变更包类型及记忆测试通过。日志保留原始失败。
5. localhost FakeProvider / 隐藏 Electron 受沙盒限制时失败，经批准重跑相同检查后通过。
6. 测试初版误用 stop 次数判断维护回收，按真实实现改为检查 reclaimAll 外部边界及注册表移除；保留活动后台工作时不回收的断言，最终通过。
7. 双语新规格缺少英文来源说明、ADR 结构/导航登记不完整导致 docs:check 失败，补齐后 80 对/520 页通过，未跳过规则。
