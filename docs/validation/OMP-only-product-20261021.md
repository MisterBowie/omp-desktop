本记录取代同日记忆排查中继续保留 Pi 执行兼容的方案；旧记录仅作当时过程证据。

## 范围与根因

截图项目的自动保存和读取开关已开启，同一项目的三个会话却全部为 Pi。
普通新建入口省略 engine，宿主和共享层默认 Pi，因此 OMP Mnemopi 从未参与。
只读诊断未读取对话正文或凭据；问题与轮次分散、worktree 无关。

按全新产品处理：OMP 是唯一可执行引擎；不迁移、导入或继续旧 Pi 会话。
磁盘已有文件与行不删除、不改引擎。应用版本 0.1.3、schema 22、原生补丁 `.7`
保持；新库 engine 默认改为 OMP，不添加历史或凭据迁移。

## 实现

| 边界 | 当前行为及主要文件 |
|---|---|
| 新建 | Renderer 普通/临时/隔离会话显式选择 OMP；不复用残留空 Pi 会话。`session-coordination.ts`、`session-slice.ts` |
| 宿主 | 默认 OMP，显式 Pi 创建被拒；列表、读取、搜索仅返回 OMP。旧 Pi 行仍保留且不改写。`sessions.rs`、`session_search.rs`、`db/schema.rs` |
| 共享契约 | 默认 OMP；Pi 标识仅用于识别退役请求，全部执行能力关闭。`packages/shared/src/engine.ts` |
| 启动与事件 | Main 不构造 Pi worker，也不接线其持久化器；OMP supervisor 管理原生进程，事件通过统一 fanout 投递。`main/index.ts`、`runtime/lifecycle.ts`、`engine-runtime.ts` |
| 旧入口 | 不发现或读取 ambient Pi 历史，不导入 transcript，不继续/分支 native Pi；IPC 明确拒绝。`session-ipc.ts`、`agent-ipc.ts`、`session-search.ts` |
| 远程 | 不打开旧 Pi Host 注册表、不自动连接；隐藏设置入口。空列表正常返回，连接/引导/删除入口拒绝。`bootstrap/startup.ts`、`remote-host-ipc.ts`、`settings-search.ts` |
| 打包 | desktop pack/dist 不构建、extraResources 不携带 Pi agent-runtime worker。OMP 原生资源和许可证保留。`apps/desktop/package.json` |
| 记忆范围 | 项目选项 hook 接受 worktree/临时会话范围，选择后不再自动退回普通项目。`AgentCapabilityLayout.tsx`、`MemorySettingsPage.tsx` |

所有受支持的无引擎创建（包括宿主的调度/插件调用）归一化并显式写入 OMP。
最终审查另发现插件导入 RPC 以及宿主 orphan/checkpoint 启动恢复仍可生成宿主历史；
现已在 RPC 边界拒绝桌面/插件导入与旧恢复，并移除 Main/宿主启动恢复接线。
真实临时数据库的启动反例验证：孤立 transcript 不生成新 OMP 行，文件字节保留。
没有批量替换包名或改写上游子模块；仍使用的模型工具库和版权声明保留。
ADR 0331、运行时与记忆双语规格、E2E 场景同步记录了此产品范围。

跨会话 ledger 消息带 origin 元数据时，现有 OMP 原生持久化不能完整保留来源，
因此在派发前明确拒绝，既不丢弃元数据也不回落 Pi。原生复制完整历史的分支、
单个子代理停止、远程 OMP 等既有能力缺口没有在本轮伪装成已实现。
