## 根因与只读事实

只读查询本机宿主元数据，确认截图中的“家政”项目存在，自动保存/读取均为 true；
三个已有会话均为 Pi。只读取项目存在性、引擎计数和两项开关，没有读取对话正文、
模型配置或凭据，也未修改安装态数据。

普通新建在 `session-coordination.ts` 仅对 isolated 传 `engine: omp`，其余入口
省略引擎；宿主兼容默认和 `normalizeEngineId` 都为 Pi。记忆开关设计上仅作用于
OMP，因此普通会话聊再多轮也不会写入 Mnemopi。该问题已通过真实 Store 工作流
回归复现：创建请求 engine 为 undefined，而非 omp。

另发现 `useAgentProjects` 只认可普通项目路径：记忆页虽额外渲染 worktree/临时
会话选项，选择后仍被 hook 判为无效而切回主项目。恢复原有范围逻辑的反例测试
实际失败：最后查询缺少 isolated 会话 id，显示主项目空页。

## 修改与保留行为

- 普通项目、临时和隔离会话均显式创建为 OMP；新建不复用空 Pi 会话。
- 已有 Pi 会话继续绑定原引擎，宿主兼容默认不变，不迁移或重放旧历史。
- 记忆页按所选项目显示 Pi 不参与自动记忆的说明，八种语言同步。
- 项目选项 hook 接受附加有效范围，记忆页将 OMP worktree/临时会话纳入同一选项源。
  选择保持原范围，不读错主项目数据库。
- 原生记忆 E2E 的保存、召回、单轮退出补存使用正常 `llmMode=smol` 配置。
  只有“两开关均关后浏览保留数据”的检查显式使用管理配置。

仍按每 4 个用户回合保存，正常退出补存；自动读取时点和目录隔离语义不变。
