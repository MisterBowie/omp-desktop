### 失败说明

1. `a key-authenticated transport is handed no askpass material`（`remote-host-ssh-password.test.mjs`）：在主检出（`main`，未含本分支改动）上单独运行同样失败（13 通过，1 失败），属于既有失败，与本次改动无关。
2. 最初全量运行中另有 5 个用例因工作树的 `upstream/` 子模块为空而失败（`source does not look like the OMP checkout`、`Cannot find module .../upstream/pi-desktop/...`）。子模块从 GitHub 克隆失败（网络不可达），因此在本工作树中把两个子模块目录替换为指向主检出同 SHA 目录的符号链接，仅用于本地验证，不提交。替换后这些用例通过。
3. 两个 e2e 因 `unexpected host call: providers.get` 失败。原因：会话提示路径新增了 `providers.get`（解析供应商地址以确定代理）。已在测试假宿主中为该方法提供与生产语义一致的供应商行，并在 `wireOmpSessions` 测试依赖中显式提供 `resolveProxy: async () => undefined`（回环 fixture 直连）。这是测试注入点，不改变被测策略。
